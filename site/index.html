为什么选择 CPAMP

CPA 负责转发，CPAMP 让一切可见、可管

把日常网关配置和长期可观测性收进同一个本地面板，回答运维中最常见的三个问题。

01请求监控与失败诊断

请求为什么失败？

CPA usage queue 中的每一条请求都会持久化到本地 SQLite。按账号或调用方 API Key 查看实时请求，几秒内定位异常。

  • 状态码、延迟、Token、缓存与 Trace 一览无余
  • 脱敏后的失败证据，不暴露原始失败体
  • 请求历史支持 JSONL 导入与导出
体验请求监控演示
02成本与用量分析

成本花在哪里？

按模型、Provider、账号、认证文件、API Key、项目、渠道和时间范围，拆解请求、Token、成本、延迟与失败。

  • 区分 input、output、reasoning 与 cache Token
  • 覆盖 service tier 与长上下文计费语义
  • 从 LiteLLM、OpenRouter 同步模型价格，并支持本地覆盖
体验用量分析演示
03账号健康、配额与自动化

账号和配额是否健康？

在浏览器本地或由 Manager Server 定时巡检 Codex 与 xAI 账号，第一时间发现失效凭证和即将耗尽的额度。

  • 配额窗口、reset 证据、凭证与工作区状态
  • 额度明确耗尽时自动受控冷却
  • 认证故障汇总到处理队列，可复核、可恢复

完整的网关管理

日常运维需要的，都在这里

覆盖官方 Management Center 的管理能力，并补上长期运维所需的工具。

Provider 与配置

管理各家 Provider、模型别名、优先级、插件、日志与系统配置。

凭证、OAuth 与 API Key

统一维护认证文件、OAuth 登录与 API Key；Muse / Meta 的 Device Flow 凭证单独管理。

Sub2API 账号导入

导入官方 Sub2API OpenAI OAuth 导出，把多账号拆分为独立的 CPA Codex 认证文件。

模型价格同步

自动同步 LiteLLM 与 OpenRouter 价格，为别名或内部模型保留本地覆盖。

历史导入导出

请求历史以 JSONL 导入或导出，迁移和归档都很方便。

随处运行

单个 Docker 容器，或 Linux、macOS、Windows 的 amd64 / arm64 原生包，可与 CPA 一同部署。

你的数据，只在你的机器上

为自托管而生

请求历史、Manager 配置、账号自动化状态和模型价格都保存在本地文件中。没有云端账号，没有遥测 SDK。

CPAMP 管理和观测经过 CPA 的流量，本身不是模型代理，也不会独立转发模型请求。

本地 SQLite请求历史持久化在你自己的磁盘上。
密钥加密保存CPA Management Key 用本地 data.key 加密。
失败证据脱敏只展示脱敏摘要，不暴露原始失败体。
MIT 开源全部源码公开，可审计、可二次开发。
